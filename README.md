## ◎ &nbsp; A Few Things I've Learned

<table>
<tr>
<td>

**Retrieval failures are more common than model failures in RAG.**
Most issues I've debugged in RAG systems weren't the LLM — they were chunking strategy, index quality, or ranking. The retrieval layer deserves as much engineering attention as the model.

</td>
</tr>
<tr>
<td>

**Latency budgets belong at the start of the design, not the end.**
The architecture decisions that determine p99 latency — caching, batching, async vs sync, model size — are mostly made early. Retrofitting them is expensive.

</td>
</tr>
<tr>
<td>

**Evals are engineering work, not a checkbox.**
Building a real evaluation pipeline before tuning means you know what "better" actually looks like. Without that, you're optimising in the dark.

</td>
</tr>
</table>
